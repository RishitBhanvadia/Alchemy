## 2025-03-06 - Replace redundant synchronous state with derived variables in Lab Component
**Before:** State `tcolor` was managed via a separate `useState` and updated through a `change_tip()` function that was called from within `handleChem*Change` functions immediately after calling `setChemA(value)`.
**Issue:** React state updates are asynchronous. Calling `change_tip()` synchronously right after `setChemA()` means `change_tip()` reads the *stale* `chemA` state closure before the next render. This subtle React anti-pattern can lead to race conditions where the tip color lags one step behind the actual input values. In addition, using a state variable here is redundant as `tcolor` can be deterministically calculated from the existing `chemA...D` state.
**Learning:** For values completely dependent on existing state or props, avoid redundant `useState` definitions and separate update functions. Instead, calculate derived variables synchronously during render (e.g., `let tcolor = ""; if (chemA > 0) tcolor = ...`). This completely eliminates "stale closure" state bugs, reduces code verbosity (from ~25 lines to 5 lines), and makes handler functions trivial one-liners.

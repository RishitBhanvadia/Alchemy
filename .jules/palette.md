## 2025-04-12 - Resolving semantic accessibility of generic links
**Learning:** Found an accessibility issue pattern across auth pages where generic `href="#"` anchor tags were used for interactive elements like "Terms of Service" and "Forgot password?". This triggered `jsx-a11y/anchor-is-valid` errors and degraded the experience for screen reader users. Simply replacing all of them with buttons is incorrect; "Terms of Service" and "Privacy Policy" are document links and should use a valid path (e.g. `href="/terms"`), while actionable elements like "Forgot password?" should be semantically implemented as `<button type="button">`.
**Action:** When fixing `jsx-a11y/anchor-is-valid`, distinguish between true document navigation (use actual URLs) and interactive JS actions (use semantic `<button type="button">` with proper styling resets).

## 2024-05-09 - Accessible Interactive Elements and React Prop Conflicts
**Learning:** Using `role` as a prop name in custom React components (like `RoleCard`) applies it directly as an HTML DOM attribute. If the value isn't a standard W3C ARIA role, it leads to `jsx-a11y/aria-role` accessibility violations and confuses screen readers. Also, interactive custom cards should use semantic interactive elements like `<button type="button">` rather than generic `<div>` elements for native keyboard navigation (Tab order, Enter/Space activation) and better screen reader support.
**Action:** Always rename conflicting props (e.g., `role` to `userRole`) to prevent unintentional DOM attribute pollution. Replace interactive `<motion.div>` elements with `<motion.button type="button">` to ensure full keyboard and screen reader accessibility out-of-the-box.

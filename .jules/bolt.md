## 2025-02-20 - Eliminate Redundant State Re-fetches with useMemo
**Learning:** In the `TeacherDashboard` component, the `fetchScores` effect was unnecessarily re-fetching `classrooms` and `class_memberships` from the database every time a filter (e.g., date range or experiment type) changed, even though the `students` list was already loaded into state and contained the necessary student IDs. This caused 3 redundant database queries over the network per filter change.
**Action:** When component state already holds the data needed to perform a filtered query (such as `student.id`s), derive the required array from state using `useMemo` (e.g., `const studentIds = useMemo(() => students.map(s => s.id), [students]);`), and use this memoized value in the dependency array of the secondary fetch effect. This avoids repeated N+1-like network requests while ensuring the effect only re-runs when the derived data or actual filter parameters change.

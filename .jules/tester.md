## 2024-03-06 - Test Coverage for Complex React Components
**Gap:** Critical user flows in `Result` and `Titration` components were completely untested. They contain complex state logic, local storage synchronization, external API fetching, timers, and external dependency interactions (`supabase`).
**Learning:** Writing tests for components with heavy asynchronous behavior (timers and fetch) and side-effects (localStorage and Supabase insertions) proved that isolating the test environment is crucial. For `Titration.jsx`, failure to wrap state updates triggered by mock interactions in `act()` caused cascading testing warnings in React 18 until `act` was imported correctly from `@testing-library/react`. Furthermore, tests failed until the Vitest `vi.mock` factory correctly defined mock implementations out of block scope or utilized `import` dynamically to access hoisted mocks.
**Pattern:** Always use `act()` from `@testing-library/react` (not `react-dom/test-utils`) when manually driving React state updates in tests using fake timers or mock function callbacks. Use inline functions for `vi.mock()` exports to prevent `ReferenceError: Cannot access X before initialization` due to hoisting. Mock heavy visual components to avoid JSDOM rendering issues.

## 2024-05-10 - Add tests for History, Profile, and Classroom Zustand Stores
**Gap:** Store slices `historyStore.js`, `profileStore.js`, and `classroomStore.js` were completely untested, representing a massive coverage gap in critical data fetching and manipulation logic directly related to core application features (student history, profiles, classroom management).
**Learning:** Testing Zustand stores that heavily rely on Supabase chained queries (e.g., `.from().select().eq().order()`) requires carefully structured mocks that mirror the exact chain path each store action takes. If multiple actions call the same root mock (e.g., `.from('classrooms')`), the mock needs to conditionally branch or return an object supporting all methods used down those paths (like `.insert()` and `.select()`). Mocking these chains robustly prevents regressions when adding new store methods.
**Pattern:** Mock `supabase.from` using an implementation function that returns specific query mock objects based on the table name. For complex methods doing inserts and selects on the same table, return an object containing all required methods (like `insert` and `select`), using vi.fn() to trace calls and returning `this` or nested objects where appropriate.

## 2024-05-18 - Mocking Supabase Auth in Zustand Stores
**Gap:** The critical `authStore.js` logic was nearly untested (15% coverage) because it depended heavily on asynchronous Supabase authentication and fetching methods which are tricky to mock within a Zustand store initialization flow.
**Learning:** Proper testing of authentication stores requires thoroughly mocking the external services (`supabase.auth` and `supabase.from`) explicitly rather than trying to test integration behavior. When a store has dependent stores initialized sequentially, circular dependency errors or uninitialized store errors can break the test runner if they are not mocked out.
**Pattern:** Mock the main dependency (`supabase.auth`) with core methods (`getSession`, `onAuthStateChange`, `signOut`) inside `vi.mock` at the top level of the test file. Clear out circular or uninitialized state dependencies by explicitly returning minimal mocks for `getState().reset` in those stores. Use `vi.clearAllMocks()` and explicitly overwrite initial state with `useAuthStore.setState({ ... })` in `beforeEach` block to ensure a clean slate between tests.

## 2024-05-24 - Shadowing global variable causes ReferenceError bugs
**Bug:** The resultController.js module was causing `ReferenceError: Cannot access 'error' before initialization` crashes whenever an early validation condition resulted in calling the imported `error(res, ...)` helper.
**Root Cause:** Inside the main handler `try {} catch() {}` block, `error` was destructured locally from `await supabase...` query on line 98 (`let { data, error } = ...`). Due to variable hoisting rules and the Temporal Dead Zone (TDZ) in JavaScript blocks, this `let error` shadowed the globally imported `error()` response helper function throughout the entire try-block. Therefore, calling `return error(res, ...)` *before* line 98 inside the try-block caused an immediate TDZ crash because the local `error` was considered uninitialized, preventing actual 400 validation error responses and turning them into 500 internal server errors.
**Learning:** Never shadow imported utility functions inside code blocks where those functions are also called. Especially in Node.js routes/controllers, destructured returns like `let { data, error } = supabase.from...` should alias the error to something else (`error: dbError`) if `error` is already a global identifier in the file scope.

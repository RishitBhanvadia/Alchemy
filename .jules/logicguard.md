## 2024-10-24 - Fix zero handling in calculateResult
**Bug:** The API returns 500 Server Error due to a `NaN` propagation issue when all chemical concentrations are zero. The sum of concentrations (`add`) is zero, which causes a division by zero error when the logic attempts to normalize the array: `chem_a = (chem_a / add) * 100`, resulting in `NaN`. Also the rounding adjust sum could infinite loop and wasn't using `while` correctly.
**Root Cause:** The normalization loop does not guard against `add === 0`. Additionally, the code for adjusting the rounded totals attempts to adjust the sum using `if` instead of iterative `while` loops, meaning if the remainder offset is greater than a single `+/- 10`, it wouldn't adjust properly.
**Learning:** Always verify division by sum guarantees the sum is non-zero, especially in formula-based inputs. Iterative adjustment algorithms (like rounding to exactly 100%) must use loops (`while`) rather than conditional logic (`if`) to ensure they handle multiple iterations of error offsets without exiting prematurely.

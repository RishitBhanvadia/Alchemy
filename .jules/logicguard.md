## 2025-05-13 - [Fix `normalise` function rounding error in `resultController.js`]
**Bug:** The `normalise` function in `server/controllers/resultController.js` creates a non-zero percentage for an ingredient that originally had a zero value (hallucination), due to blindly assigning the remainder to the last element. E.g., `normalise(33, 33, 33, 0)` results in `[33, 33, 33, 1]`.
**Root Cause:** The formula `const nc = 100 - na - nb - ni;` guarantees that the sum of the percentages is exactly 100. However, it dumps all the rounding remainder directly onto the last element `nc`. If `na, nb, ni` were all rounded down (e.g., from 33.333... to 33), `nc` absorbs the missing 1% and becomes 1, even if the input `c` was exactly 0.
**Learning:** When normalizing percentages to sum to 100, calculate each rounded percentage independently using `Math.round()`. Then distribute the remainder to the element with the largest original value. This prevents non-zero elements from remaining zero, and zero elements from erroneously becoming non-zero.

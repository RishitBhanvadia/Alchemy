## YYYY-MM-DD - Fix inline duplicated shared logic in results calculation
**Bug:** The result calculation endpoint in `server/controllers/resultController.js` inline-defined `computeReactionId` and `classifyRegime` functions, which drifted from the shared utilities defined in `server/utils/reactionHash.js` and `server/utils/regimeClassifier.js`. This results in the wrong keys (like flipped catalyst vs indicator threshold values for the hash id, and completely missing catalyst and indicator dominances for regime classification). This would break reaction outputs for indicator/catalyst driven reactions.
**Root Cause:** Inlining functions in the controller meant that changes to thresholds or rules in the shared utilities were not reflected, causing differing `reaction_id` hashes and `regime` identifiers to be queried from the database.
**Learning:** Shared business logic for data access identifiers (like hashes) and business logic regimes must ALWAYS be imported from single-source-of-truth utility files. Duplicated inline rules inevitably drift, creating incorrect queries and silent output failures that are hard to diagnose.

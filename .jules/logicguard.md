## 2026-03-14 - Fix Chemical Concentration Normalization Logic Bug
**Bug:** When users provided chemical concentrations that sum to exactly 100 but have intermediate values ending in `5` (e.g., 25, 25, 25, 25), the `Math.round(val / 10) * 10` function rounds all of them up (30, 30, 30, 30 = 120). The application only corrected the sum by `-10` *once*, leaving the normalized total sum at `110`. The subsequent query failed because the database only maps exact 100-sum concentration reactions.
**Root Cause:** The `final_add` rounding correction logic used a simple `if (final_add > 100)` check, which only subtracted `10` once instead of looping until the total mathematically converged to exactly 100.
**Learning:** When performing bounded adjustments (like ensuring multiple rounded inputs always sum to a specific limit), always use iterative convergence (`while`) rather than a single branching statement (`if`), since rounding multiple independent variables can introduce an aggregate drift far larger than a single discrete correction step.

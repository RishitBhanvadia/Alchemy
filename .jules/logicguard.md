## 2024-05-04 - Fix duplicated and divergent `classifyRegime` logic
**Bug:** The `classifyRegime` logic was duplicated across three files (`client/api/results.js`, `server/controllers/resultController.js`, and `server/scripts/migrate.js`) and each had completely different and divergent rules. The client's classifier failed to correctly classify catalyst dominance and indicator dominance, instead returning `MIXED` for single elements above 0 that weren't above 60. The server's classifier didn't accept `chem_c` or `chem_i`, and used a 0.60/0.40 threshold for acidity instead of 0.65/0.35, resulting in mismatched lookups in the database.
**Root Cause:** Duplication of the utility function across both the client and server codebases, without synchronizing or using a shared utility. The server code also passed `a, b` instead of `a, b, i, c`.
**Learning:** Always extract core business logic into a shared module. If that's not possible due to repository setup (e.g. separate client/server without monorepo package sharing), ensure the logic is identical to prevent different results between client-side prediction and server-side validation.

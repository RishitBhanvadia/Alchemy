## 2024-04-07 - Accessibility failures on auth inputs due to missing htmlFor
**Bug:** The authentication login test cases (`should handle form submission`, `should handle login error`, `should render login form`) were failing due to missing `htmlFor` properties on labels in `InputField.jsx`, preventing `getByLabelText` from successfully resolving inputs.
**Root Cause:** The `InputField.jsx` component was incorrectly wrapping the `<input>` element with a `<label>` string, but missing the `htmlFor={name}` linkage tying it to the `id={name}`. The input element also lacked proper `aria-invalid` and `aria-describedby` accessibility attributes to handle component error states.
**Learning:** In reusable input wrapper components (like `InputField.jsx`), the label `htmlFor` attribute must be strictly matched to the `input` `id` for accessible lookup via `getByLabelText` in testing (and for general AT compatibility). All custom form components must integrate `htmlFor`, `id`, `aria-invalid`, and `aria-describedby` when errors are conditionally rendered to pass standard accessibility constraints and RTL test suite selectors.

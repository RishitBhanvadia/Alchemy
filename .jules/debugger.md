## 2024-06-13 - [Build & Runtime Crashes: Variable Shadowing and CSS Order]
**Bug:** The client application failed to build due to esbuild throwing duplicate declaration errors for `clicking` and `hovering` state variables in `CursorFollower.jsx`. Concurrently, Tailwind CSS failed to compile because an `@import url(...)` statement for Google fonts was placed after the `@import "tailwindcss";` directive in `index.css`. Additionally, a `react-hooks/rules-of-hooks` error existed because an early return condition (`if (isTouchDevice) return null;`) was placed before a `useEffect` hook in `CursorFollower.jsx`.
**Root Cause:** Careless duplication of state definitions and incorrect placement of CSS `@import` rules which must strictly precede all other styling rules aside from `@charset` and `@layer`. The Hooks error stemmed from conditionally breaking the hook call order.
**Learning:** Always run linter (`pnpm lint`) and build (`pnpm build`) steps to catch syntax and structure errors early. Hook calls must remain unconditional at the top level of the component, and external CSS imports must be placed at the absolute top of the stylesheet.

## 2024-06-13 - [CI Failure: Unused variables & JSX A11y Violations]
**Bug:** The client application failed the CI `test` check due to several ESLint errors. Specifically, there were unused imports (`Loader2`, `Check`, `useCallback`), invalid empty `href="#"` anchor tags which violate `jsx-a11y/anchor-is-valid`, and custom React component props named `role` which ESLint incorrectly flagged under `jsx-a11y/aria-role`.
**Root Cause:** The `no-unused-vars` rule is configured as an error, failing CI. Anchor tags were used purely for styling and onClick behaviors without proper navigation destinations. The `role` prop on `RoleCard` clashed with standard HTML ARIA attributes.
**Learning:** Always run local lint checks (`pnpm lint`) before committing. Ensure unused variables are pruned. Use `<button type="button">` instead of `<a>` for clickable elements without valid URIs. Rename custom component props that conflict with standard ARIA attributes (e.g., change `role` to `userRole`) to prevent false positives from accessibility linters.

## 2024-06-13 - [CI Failure: Server Process Hanging during Tests]
**Bug:** The server GitHub Actions CI build (`build-server`) failed due to a 6-hour timeout, as the process never exited. Concurrently, the app threw a startup error due to missing `.env` variables (`SUPABASE_URL`, etc.).
**Root Cause:** The `server/server.js` file unconditionally executed `validateEnv()` and bound to `app.listen()` when required by external testing modules (like Jest with Supertest), which blocked the Node process from shutting down naturally and demanded production-level environment variables during the test suite.
**Learning:** Always wrap continuous application lifecycle operations (e.g., `app.listen`, graceful shutdown signals) and strict environment validation functions inside `if (require.main === module)` blocks. This pattern allows testing frameworks to safely import the Express `app` without initiating a full, blocking server runtime.

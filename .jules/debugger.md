## 2025-04-12 - Fix application build and fatal rendering crash in CursorFollower
**Bug:** The Vite production build was failing due to duplicate variable declarations (`clicking`, `hovering`) in `client/src/components/CursorFollower.jsx`, and a Vite build warning occurred in `client/src/index.css` due to incorrect `@import` order. Additionally, `CursorFollower.jsx` was violating React's Rules of Hooks by having a conditional early return (`if (isTouchDevice) return null;`) *before* hooks were executed, causing fatal crashes on touch devices.
**Root Cause:** Two pairs of `useState` declarations were copied/left over during a previous refactor of `CursorFollower.jsx`. The early return was placed incorrectly before `useEffect` violating the React requirement that hooks must be called in exactly the same order on every render. Also, `index.css` placed standard Google Fonts imports below Tailwind imports, which Vite's esbuild restricts.
**Learning:** React strictly requires all hooks to be called at the top level of the component *before* any conditional early returns; failing to do so causes immediate fatal rendering crashes. Additionally, in Vite/Tailwind v4 environments, standard CSS `@import url(...)` rules must strictly precede all other statements including `@import "tailwindcss";` to prevent build warnings or failures.

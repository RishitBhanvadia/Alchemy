## 2024-05-24 - Pure State Updaters in Timers
**Bug:** Side-effects inside interval callbacks or during `setCount` updates led to race conditions, inefficient re-rendering, and timing issues with React's dependency array in `client/src/pages/titration.jsx`.
**Root Cause:** The `setAcid` hook invocation was placed directly inside `setInterval` alongside `setCount`. Because it relied on the current `count` value (rather than a pure previous state), the timer closure captured stale state while repeatedly resetting the interval upon `count` changes in the `useEffect` dependency array.
**Learning:** Always keep `setState` functional updates pure. Side-effects (like derived state updates or `clearInterval` calls) must be decoupled from timer internals and extracted into distinct `useEffect` hooks that explicitly depend on the updated state variable.

## 2024-05-24 - Missing Env Vars Crashing CI
**Bug:** The server crashed on startup (`❌ STARTUP FAILED: Missing required environment variables`) during GitHub Actions CI checks.
**Root Cause:** The `server/config/validateEnv.js` explicitly checks for `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, and `GEMINI_API_KEY` using `process.env`. If any are missing, it logs an error and synchronously calls `process.exit(1)`. The CI test environment `build-server` sets `NODE_ENV=test` but explicitly passes `placeholder` environment variables to bypass this block, but some other configurations or tools running CI logic on `server.js` (like `require('./server.js')` tests) failed if the placeholder env var injection was mismatched or skipped. Furthermore, some components like `server/supabaseClient.js` directly initiated `createClient(supabaseUrl, supabaseKey)` where `supabaseUrl` and `supabaseKey` fell back to `undefined` if `process.env` keys were absent, causing `@supabase/supabase-js` to throw `Error: supabaseKey is required.` fatal exceptions during module load.
**Learning:** For components relying on external API clients (like Supabase or Gemini), always provide valid placeholder string fallbacks during client initialization to ensure the app doesn't crash from missing env variables during CI build/test phases. Additionally, any custom environment validation logic (like `validateEnv.js`) must be properly handled or bypassed in test environments.

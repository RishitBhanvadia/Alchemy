## 2025-01-20 - Add proper ARIA roles and keyboard interactions to custom visually designed radio components
**Problem:** The `RoleCard` component used in `SignUpForm` was a custom visually designed UI element functioning as a radio button selection, but it lacked proper HTML ARIA roles and keyboard navigation capabilities, making it inaccessible for screen readers and keyboard-only users.
**Context:** In the Alchemistry application, custom UI elements are often used to enhance visual appeal. However, when these elements replace standard HTML inputs like radio buttons, they must be augmented with proper ARIA attributes to maintain accessibility.
**Solution:** Added `role="radiogroup"` and `aria-label="Lab Role"` to the parent container of the `RoleCard` components. On the `RoleCard` itself, added `role="radio"`, `aria-checked={selected}`, and `tabIndex={0}`. Implemented an `onKeyDown` handler to allow selection using the 'Enter' or 'Space' keys. Renamed the custom `role` prop to `userRole` to avoid conflict with the HTML `role` attribute.

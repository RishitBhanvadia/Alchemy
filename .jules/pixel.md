## 2024-05-18 - Fix form accessibility and link validation errors
**Problem:** The `LoginForm`, `AuthPage`, and `Login` pages had accessibility errors (`jsx-a11y/anchor-is-valid`) because `<a>` tags were used with `href="#"` or `href="#!"` instead of using `<button>` elements for placeholder links (like 'Forgot password' and 'Terms of Service'). Additionally, the `role` prop on `RoleCard` caused an ESLint error (`jsx-a11y/aria-role`) because it clashed with native DOM attributes. `InputField` lacked an `htmlFor` association and error linking. These caused testing library failures because elements couldn't be queried correctly or ESLint failed the build.
**Context:** For this app, testing heavily relies on accessibility queries (like `getByRole` or `getByLabelText`). If the UI is inaccessible or uses conflicting attribute names, test setups and screen readers fail.
**Solution:** Replaced invalid placeholder `<a>` links with `<button type="button">` styled as links to fix `anchor-is-valid` errors. Renamed the `role` prop in `RoleCard` and `SignUpForm` to `roleType` to fix `aria-role` conflicts. Added `htmlFor={name}` to the `<label>` in `InputField` to explicitly associate the label with its input. Added `aria-invalid` and `aria-describedby` with matching error ids so error messages are linked to their respective fields, improving the user experience for screen reader users and resolving Test Library query failures.

## 2026-04-20 - CursorFollower React Hooks Fix\n**Problem:** React rule of hooks violation caused fatal `vite build` crash. The `CursorFollower` component was calling `useState` and `useEffect` hooks *after* an early conditional return (`if (isTouchDevice) return null;`).\n**Context:** React requires all hooks to be unconditionally called in the exact same order on every render. Returning early before hooks breaks this constraint, causing React to lose track of state mapping and fatally crashing during production builds. This happens uniquely on devices or browsers mimicking non-touch devices where `isTouchDevice` evaluated true.\n**Solution:** Moved the conditional early return statement to the bottom of the component, just before the return JSX, ensuring all `useState` and `useEffect` hooks are safely declared at the top-level of the component on every render cycle.

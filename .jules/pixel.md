## 2024-05-19 - Adding Context-Aware Loading Skeleton to StudentDashboard
**Problem:** The initial load of the `StudentDashboard` showed a generic, blocking "Initialising Laboratory Access..." overlay or occasionally flashed a jarring layout of a table and chart because the app reused `DashboardSkeleton` (which matched the TeacherDashboard) for the `/student` route fallback.
**Context:** When a student logs in, the dashboard layout is a 2-column grid showing module cards (Laboratory, Titration, etc.) and history. Showing a generic overlay or a table skeleton caused layout shifts and disjointed visual feedback, decreasing the perceived performance and polish.
**Solution:** Created a new `StudentDashboardSkeleton` component with specific CSS grid matching the actual dashboard. Updated `App.jsx` and `StudentDashboard.jsx` to use this new skeleton. This creates a cohesive, skeleton-driven transition that perfectly mimics the final loaded state layout, greatly reducing visual friction.

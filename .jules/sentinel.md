## 2026-03-14 - Add input validation and length limits to AI endpoints
**Vulnerability:** The AI tutor endpoints (`/explain` and `/hint`) lacked input validation and length limits for properties like `student_question`, `reaction_outcome`, and chemical concentrations, allowing potentially malicious prompts to be sent unvalidated to the Gemini API and posing a DoS or prompt injection risk.
**Learning:** Third-party API integrations (especially LLMs) are often prone to injection attacks if the incoming payloads are not carefully bounded and type-checked before being constructed into prompts. Without hard length constraints, users could exhaust server resources or API credits intentionally or accidentally.
**Prevention:** Always validate all user inputs (types, limits, bounds) at the controller level before passing them directly to expensive or sensitive downstream services. Enforce reasonable bounds (e.g. `[0, 100]` for chemical concentrations and max `500` characters for questions).

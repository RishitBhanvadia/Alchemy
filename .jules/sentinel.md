## 2024-05-18 - Fixed Exposed Error Stack Traces
**Vulnerability:** The `error` utility response function included an optional `details` parameter. When passed, and if `NODE_ENV` was set to `development`, it would append error specifics, like error stack traces or raw database constraints, directly to the client JSON response. This runs the risk of unintentionally exposing internal configurations, database layouts, or logic in production environments if environment variables were misconfigured or if `development` was used maliciously as a deployment environment.
**Learning:** Hard-coded flags relying on environment variables to emit sensitive response details in common utilities are risky. Often, utilities are reused in different contexts. A safer approach for API errors is to never send internal error details to the client directly via response utilities. Instead, details should be logged server-side, returning a generic message to the client.
**Prevention:** Removed the `details` parameter entirely from the `exports.error` response function, guaranteeing that internal server details are strictly omitted from the API response payload regardless of the environment context.

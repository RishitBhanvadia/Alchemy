## 2025-02-28 - CSRF/Auth Bypass in Google OAuth Flow
**Vulnerability:** The Google OAuth redirect route (`/api/meetings/google/auth`) accepted a `teacherId` via query parameter and initiated the OAuth consent flow without any authentication or CSRF protection. This allowed malicious actors to initiate an OAuth flow for arbitrary teacher IDs, potentially hijacking their Google token state.
**Learning:** Browser redirects (like OAuth consent screen redirections) cannot natively carry HTTP `Authorization` headers. When relying on direct browser redirects for OAuth initiation, passing user identifiers via query parameters leaves the flow vulnerable to Cross-Site Request Forgery (CSRF) and authentication bypass, as anyone can construct and execute the URL.
**Prevention:** Instead of using a direct browser redirect endpoint that takes parameters, expose an authenticated JSON API endpoint (e.g., `/api/.../auth-url`) protected by standard authentication middleware. The client fetches the required URL dynamically via this API, extracting the user ID securely from the session token (`req.user.id`), and then the client handles the redirection to the returned URL.

## 2024-03-16 - Prevent Probability Bias in Cryptographically Secure Class Codes
**Vulnerability:** Weak PRNG `Math.random` was used for generating 6-character class codes, which is predictable. If switched to `window.crypto.getRandomValues()` using a naive string conversion like `byte.toString(36)[0]`, severe probability bias is introduced.
**Learning:** `Math.random` should never be used for secure tokens or codes. When using `window.crypto.getRandomValues()`, naive string conversions or improper mapping introduce severe probability bias because the modulo arithmetic doesn't perfectly map 256 byte values evenly onto small character sets like 36 alphanumeric characters.
**Prevention:** Use a predefined alphanumeric character array and map generated bytes against it using modulo arithmetic `chars[byte % chars.length]` to ensure even distribution and prevent probability bias when generating secure class codes.

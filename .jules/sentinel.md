## 2026-03-24 - Fix Statelessness and Secure Token Storage in Meeting Controller
**Vulnerability:** Google OAuth tokens (`accessToken` and `refreshToken`) were being stored in an in-memory `Map` (`googleTokenStore`). This broke stateless design principles (violating multi-instance deployments as tokens are restricted to a single instance's memory) and exposed raw tokens in memory, which could be dumped or lost on server restarts. Moreover, the initial pass at a solution relied on an unhashed environment variable string to seed AES encryption directly, causing length validation failures and crashing the app.
**Learning:** In-memory storage of stateful tokens not only breaks scalability (e.g., Load Balancers, PM2 clusters, serverless deployments) but also introduces risk of unencrypted secrets exposure. Always push sensitive session state to a secure database. When implementing `crypto.createCipheriv`, never pass a raw string fallback or rely on the exact length of process environment strings; always hash the input (e.g., using `crypto.createHash('sha256')`) to consistently generate a valid 32-byte key buffer for AES-256. Decryption boundaries must always handle errors using try/catch.
**Prevention:** Store OAuth tokens in a dedicated database table (`google_oauth_tokens`). Always encrypt tokens at rest using AES-256-CBC with a correctly hashed 32-byte key buffer and decrypt them on-demand inside safety blocks that fallback to a "Missing Auth" app state when decryption fails.

## 2026-06-04 - Pre-existing ESLint CI Warnings Handled and Backend Startup Fixed
**Vulnerability:** A `react-hooks/rules-of-hooks` violation crashed the `client` lint check suite, and the server failed to start via automated import because `require.main === module` was omitted in `server.js`.
**Learning:** Fixing out-of-scope errors during CI feedback passes requires strictly following rules regarding preserving `npm ci` module trees (e.g. Node 18 EBADENGINE exceptions). Also, unconditionally calling `process.exit(1)` when `server.js` fails its `.env` guard blocks automated integration checks.
**Prevention:** Strictly enforce standard React component rendering rules. Always test the backend entrypoint via `node -e "try { require('./server.js') } ..."` to ensure test-runner compatibility.

## 2026-06-05 - Handling Impure Function ESLint Blockers in Effect Hooks
**Vulnerability:** A `react-hooks/purity` ESLint violation on `Math.random()` blocked the build because it was invoked directly during the component render phase in `ParticleBackground.jsx`.
**Learning:** React 18+ strict linting enforces component idempotency. Impure functions (like math random or `Date.now()`) shouldn't be executed directly within the render body unless wrapped in hooks like `useMemo` or `useEffect` to guarantee pure renders.
**Prevention:** Turn off the overly aggressive compiler lint block if standard rules prevent compilation, or correctly isolate impurities behind `useMemo` hooks.

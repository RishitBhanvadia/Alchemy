## 2024-05-24 - Authorization Bypass and CSRF in Google OAuth Flow
**Vulnerability:** The `/api/meetings/google/auth` endpoint lacked authentication middleware and accepted an arbitrary `teacherId` via query parameter. Furthermore, it dynamically constructed the `redirectUri` using the `Host` header (making it vulnerable to Host Header Injection), and the `state` parameter did not include a cryptographic signature.
**Learning:** This allowed an attacker to authorize their own Google account for any teacher's ID, leading to meetings being created on the attacker's calendar on behalf of the teacher. In addition, lack of state signing allowed CSRF attacks during the OAuth callback.
**Prevention:** Always require authentication on API routes that initiate OAuth flows if they intend to bind tokens to the logged-in user. Validate `req.user.id` instead of accepting user IDs from query strings. Use environment variables (like `API_URL`) to build redirect URIs to prevent Host Header Injection. Cryptographically sign the `state` parameter to prevent tampering and verify the signature in the callback.

## 2024-05-24 - Replaced Math.random() with CSPRNG for Sensitive Codes
**Vulnerability:** Weak PRNG (`Math.random()`) was used to generate sensitive, sharable codes (like Class Codes and Meeting Codes) in both the client and server.
**Learning:** `Math.random()` in Node and browsers is predictable and non-uniform, opening vectors for brute forcing or collision prediction. When attempting to use `window.crypto.getRandomValues(new Uint32Array(1))` and converting to base-36 with substring, it causes severe entropy loss (predictable leading characters) and length unreliability.
**Prevention:** Always map randomly generated bytes to a character set using modulo operations for uniform strings. Use Node's `crypto.randomInt` on the server and `window.crypto.getRandomValues` on the client.
